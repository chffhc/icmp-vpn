# ICMP VPN v1 (development MVP)

Outcome: unrooted Android VpnService routes IPv4 TCP/UDP/DNS via authenticated ICMP echo to Linux TUN + NAT. IPv6 is captured and blocked, not claimed supported. No live remote deployment without host details. Only own/authorized networks.

## Fixed protocol contract
Outer transport: IPv4 ICMP echo request (8) client -> server, echo reply (0) server -> client. Android uses android.system.Os.socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP), requires INTERNET permission but no raw socket/root. protect(fd) before connect to literal public server IPv4. Linux raw socket requires CAP_NET_RAW; TUN configuration CAP_NET_ADMIN. Android ping socket kernel may rewrite identifier, so server MUST mirror received identifier + ICMP sequence in response, not use identifier as protocol session identity. Linux raw receive includes IPv4 header (variable IHL); Android ping socket receive starts at ICMP header. ICMP checksum covers header and encrypted frame. Kernel automatic unencrypted echo replies can coexist; client rejects their direction-specific authentication. Do not change global echo policy silently.

Payload = 24-byte authenticated header + AES-256-GCM ciphertext/tag (16-byte tag).
Header big endian: magic ASCII IVP1 (4); version 1 (uint8); kind (uint8); session ID (uint64 nonzero random); per-direction sequence (uint64 starting 1, never reused); plaintext length (uint16). kind 0=POLL/idle (empty), 1=IP packet, 2=HELLO (empty client request; server reply plaintext ASCII "10.77.0.2|1200"), 3=CLOSE (empty). All header bytes are GCM AAD. Reject unknown version/kind, lengths, trailing data, nonempty POLL/CLOSE, sequence zero, zero session. Maximum plaintext length 1200. Entire ICMP datagram <= 1248 bytes (8+24+1200+16).
PSK = exactly 32 random bytes, entered as 64 hex characters in Android, stored in server key file (not CLI argument/env). Derive key per session and direction as HMAC-SHA256(key=PSK, data=ASCII "icmp-vpn-v1/" || direction byte || big-endian sessionID). Direction byte 0 client->server, 1 server->client. GCM nonce = four zero bytes || big-endian sequence. Separate direction keys prevent reflected kernel echoes from authenticating. No forward secrecy, no custom handshake claims.
Replay window 32768 sequence numbers per direction in the high-latency endpoints: the highest accepted sequence and the preceding 32767 (distance <32768), inclusive. Only update AFTER successful authentication, source/session binding and complete semantic validation. Handle reorder within window, reject duplicates/stale/zero, compare uint64 sequences unsigned, and never accept counter wrap. Server uses a circular bitmap (4096 bytes; no per-packet full bitmap shift). The IVP1 wire bytes, key derivation, nonce and HELLO configuration are unchanged; legacy 256-window clients remain wire-compatible but retain their smaller downstream reorder tolerance. Replay window size is local policy, not negotiated. Server sequence never reset for same session (even repeated HELLO), wrap is fatal; client uses fresh cryptographic session ID per connection. Android may accept echoed ICMP sequence out of order, but protocol replay gates remain authoritative.

## Single-client v1 semantics
Linux TUN icmpvpn0 local 10.77.0.1/24, Android 10.77.0.2/32. Wire/inner IPv4 ceiling 1200 (HELLO "10.77.0.2|1200", Linux TUN MTU1200). Android interface MTU is 1280 because Android rejects an IPv6 TUN address below 1280 (verified API-36 emulator: "Cannot set address"); the client clamps TCP MSS to 1160 and returns local ICMP frag-needed (MTU1200) for oversized IPv4 instead of sending it. Only one active authenticated session, idle timeout120s. Bind active session to source IPv4; migration starts a new connection/session, no silent takeover of active session. HELLO required before IP/POLL. Duplicate/replayed packets must not deliver data or consume downstream queue. Invalid/new sessions cannot evict authenticated session or allocate unbounded state. On expired/CLOSE session retain tombstone/replay binding for used session IDs (bounded safe refusal rather than nonce reuse). Additionally persist ALL first-accepted session IDs in a locked, bounded, 0600 durable journal for the PSK lifetime; append and fsync BEFORE any first-session reply. A restarted server rejects every previously journaled SID, requiring a fresh client connection/SID. Refuse startup on corrupt/truncated journal, refuse new sessions on journal I/O/full failure, and prevent concurrent servers sharing the journal with an exclusive lock. Never reset/delete this journal while retaining the same PSK. This prevents replayed HELLO from resetting the server AES-GCM nonce after restart. Default downstream queue is FIFO256, discarding oldest on overflow with explicit QueueDropped metric; no age/AQM drops. --queue-discipline fifo|fq-codel selects the local queue; fq-codel is opt-in experimental only (not the deployment default). --queue-limit 1..4096 defaults to 256. Unknown disciplines and invalid CLI limits fail before key/ledger/network access. Experimental FQ-CoDel uses 30ms target, 200ms interval and a 300ms sojourn backstop (preserving the last packet), reports overflow and CoDel drops separately, and is simplified rather than RFC-conformant. The high-latency build retains the FIFO compatibility default; do not reset the PSK/session ledger or automatically deploy the experimental queue. One echo reply per validated request, no unsolicited echo replies. Authenticated IP request validates IPv4 version/IHL/total len/source=10.77.0.2, rejects fragmented traffic in MVP, forwards to TUN; server answers with queued packet or idle. TUN reads validate destination=10.77.0.2, <=1200, enqueue only while live session. IPv6 unsupported and never direct fallback. Client captures ::/0 + private IPv6 address and drops IPv6 packets. Outer IPv4 only. Keep server destination enforcement away from changing user routes until explicit deployment.
Client send IP or POLL every ~20ms while idle; poll again promptly on downstream data. Bounded queue, no busy loop/unbounded threads. IP datagrams best effort (TCP provides its own reliability), UDP retains normal loss semantics; no claim lossless UDP/production performance. ICMP filtering/rate limits are explicit limitations.
